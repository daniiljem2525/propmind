# Автоматизация: заявки Arendora → заказы на Профи.ру

Фоновый воркер берёт заявки из Supabase, открывает браузер под вашим
залогиненным аккаунтом Профи.ру, сам проходит мастер «Создать заказ»
(услуга → способ подбора → уточняющие вопросы → срок → адрес → бюджет →
описание) и публикует заказ. Результат пишется обратно в Supabase.

Авито пока не подключён (в таблице зарезервирован `platform='avito'`):
у Авито нет публичного API на создание заказов, драйвер добавляется
по той же схеме, что и `profi.mjs`.

## Как это работает

```
заявка в Arendora (maintenance_requests)
        │  кнопка «Отправить на Профи» в карточке заявки
        ▼
очередь automation_orders (status=pending)
        │  воркер опрашивает Supabase каждые POLL_INTERVAL_SEC
        ▼
Playwright открывает браузер с сохранённым профилем Профи.ру
        ▼
мастер «Создать заказ» заполнен и отправлен
        ▼
automation_orders: status=sent + result_url (или failed + error)
```

## Установка (один раз, на компьютере, где будет работать воркер)

```bash
cd automation
copy .env.example .env        # Windows; на mac/linux: cp .env.example .env
# заполните .env: SUPABASE_URL и SUPABASE_SERVICE_KEY
npm run setup                 # npm install + браузер Chromium для Playwright
npm run login                 # откроется браузер — войдите в Профи.ру один раз
```

Профиль с сессией сохранится в `automation/state/profi-profile`, дальше
логин не требуется. Не переносите эту папку и не публикуйте её.

В schema.sql должна быть применена секция 11 (таблица `automation_orders`) —
выполните её на вашем Supabase, если база разворачивалась раньше.

## Запуск

```bash
npm start                     # фоновый режим, невидимый браузер
```

Полезные режимы в `.env`:

- `HEADLESS=0` — видно окно браузера (первый запуск рекомендуется так).
- `DRY_RUN=1` — воркер проходит все шаги мастера, но финальную кнопку
  не нажимает: удобно проверить заполнение без реальной отправки.
- `AUTO_ENQUEUE_NEW_REQUESTS=1` — ставить в очередь автоматически каждую
  новую заявку (по умолчанию выключено: заказ уходит только по кнопке).
- `DEFAULT_ADDRESS` — адрес объекта, если он не передан с заказом.

Для работы в фоне на Windows: `start /b npm start` или служба через NSSM.

## Статусы заказов в очереди

| status    | meaning                                  |
| --------- | ---------------------------------------- |
| `pending` | ждёт воркера                             |
| `running` | браузер прямо сейчас создаёт заказ       |
| `sent`    | опубликован, в `result_url` адрес заказа |
| `failed`  | не удался, причина в `error`             |

## Важно

- Профи.ру не даёт публичного API на создание заказов, поэтому используется
  браузерная автоматизация — это формально против правил площадки. Аккаунт
  могут ограничить; используйте на свой риск и не создавайте заказы массово.
- Если Профи запросит SMS/капчу (обычно только при новом входе), воркер
  остановится с ошибкой `NeedsLogin` — запустите `npm run login` снова.
- Селекторы сняты с живого сайта 10.2026; при редизайне Профи правьте
  `src/profi.mjs`.
